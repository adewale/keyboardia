Piano roll layout options

Proposal only: PR #127 is spec and mocks; application integration is deferred. How sequencers and DAWs place track controls, the step grid and the note editor relative to each other, what that implies for Keyboardia's control column, and six arrangements ranked against alignment, row rhythm and tessellation. The #1 cards show the adopted PR #127 proposal after the consistency audit. Other cards preserve historical candidate layouts and their original trade-offs, including their wider columns.

Two patterns cover every tool above. Either the editor is a separate pane with its own keyboard and its own controls to the left of it, or the editor replaces the all-track grid for one instrument. No tool widens the track header to make room for the editor, which is what Keyboardia does today, and none inserts an editor between two track rows.

Constraints the arrangement has to respect

  • Column alignment. Every step column, in every row and in the roll, sits on a 39px pitch (36px cell + 3px ordinary gap), with 8px extra at each 16-step page boundary. The 11px page band is shared by the ruler, cells, property lanes and dock. The adopted keyboard and control column are both 134px, with the common 8px gap before step 1 at x=142px. The dock column contains an 18px range rail and 116px keyboard.
  • Row rhythm. Track rows repeat at one height. The eye scans down a column to see which instruments hit a beat together. Anything inserted between rows that is not a row of cells breaks the scan.
  • Tessellation. Rows are the same width and height and butt against each other, so the grid reads as one surface. A drawer under one track, and equally a 400px roll under one track, splits that surface in two.
  • Row width is load-bearing. Changing the control column's width moves the drop target for drag-reorder during playback, which the project's lesson 62 records as fragile. Moving width between left and right of the row keeps the total, which is a different proposition from changing it.
  • Discoverability. Transpose and step count are the two controls people reach for while composing. Hiding them costs more than hiding pattern tools or the instrument picker.
  • Shared horizontal scroll. All rows and the editor scroll together, and sticky columns on the left (or right) must be children of that one scroller.

Adopted consistency contract

  • Compact controls. Width 134 = grip 12 + body 110 + gap 4 + padding 8. Two 17px lines with a 2px gap make 36px. Five 20 × 17px line-two items have 2px gaps within groups and 4px between groups, totalling 110px.
  • Row geometry. Desktop: 44px row with 4px padding above and below the 36px block, plus 2px gap = 46px pitch. Landscape: identity 17 + gap 2 + controls 28 + padding 1 = 48px row, plus 2px gap = 50px pitch; reserve scroll space so the rows clear the dock.
  • One toolbar. Notes, Step and Track each have a fixed 48px toolbar, single line with horizontal overflow. Chips, tools, tie toggle, pattern buttons and both dropdown variants are 28px high, radius 4px; dropdowns use the existing variables. The adopted cards let you switch panes and all track tabs; the other controls are intentionally disabled integration previews.
  • Pitch stays visible. MIDI 12..108 is a full chromatic range. Scale lock snaps new or moved notes without changing existing pitches or removing rows. Drum tracks open Step and Track; Notes is melodic only.
  • Shared velocity colour. Cells and bars use the same CSS token formula: accent mixed toward surface by velocity. Each cell/bar evaluates --note-velocity-fill locally using normalized --note-velocity; no lock means 1.0. The seeded 0.3, 0.5, 0.8 and 1.0 locks demonstrate the ramp; no white fill or volume badge. Cells carry at most velocity colour, a pitch/tie contour and a purple lock border.
  • State and typography. Docked state is a 2px accent edge on the control block only. Chrome accent marks active chips and ♪. Canonical --piano-key-*, --piano-grid-{step,beat,bar,octave,black-row} and --note-velocity-{accent,surface,fill} tokens belong in index.css. Grid alphas are 4.5%, 10%, 22%, 16% white and 22% black respectively. Values use --font-mono; toolbar labels 11/500, 0.5px tracking, uppercase; line-two glyphs 10/700; keyboard and bar labels 10/500.
