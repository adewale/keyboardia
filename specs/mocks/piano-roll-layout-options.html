Piano roll layout options

How sequencers and DAWs place track controls, the step grid and the note editor relative to each other, what that implies for Keyboardia's control column, and six arrangements ranked against alignment, row rhythm and tessellation. Two patterns cover every tool above. Either the editor is a separate pane with its own keyboard and its own controls to the left of it, or the editor replaces the all-track grid for one instrument. No tool widens the track header to make room for the editor, which is what Keyboardia does today, and none inserts an editor between two track rows.

Constraints the arrangement has to respect

  • Column alignment. Every step column, in every row and in the roll, sits on the same 39px pitch so that the same beat is the same x position everywhere. The roll's left edge is therefore pinned to the control column's right edge, and the keyboard is exactly as wide as that column.
  • Row rhythm. Track rows repeat at one height. The eye scans down a column to see which instruments hit a beat together. Anything inserted between rows that is not a row of cells breaks the scan.
  • Tessellation. Rows are the same width and height and butt against each other, so the grid reads as one surface. A drawer under one track, and equally a 400px roll under one track, splits that surface in two.
  • Row width is load-bearing. Changing the control column's width moves the drop target for drag-reorder during playback, which the project's lesson 62 records as fragile. Moving width between left and right of the row keeps the total, which is a different proposition from changing it.
  • Discoverability. Transpose and step count are the two controls people reach for while composing. Hiding them costs more than hiding pattern tools or the instrument picker.
  • Shared horizontal scroll. All rows and the editor scroll together, and sticky columns on the left (or right) must be children of that one scroller.
